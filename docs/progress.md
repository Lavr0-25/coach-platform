### Сделано

1. **Лимит скриншотов** (`/feedback`): multiple-загрузка, до 5 файлов на обращение (MAX_IMAGES), неподходящие файлы пропускаются с сообщением, остальные грузятся.

Авто-редирект на главную после отправки убран.
3. **Server actions** (`app/actions/feedbackActions.ts`): updateMyFeedback / deleteMyFeedback — проверка владельца + статус «Новое» прямо в запросе (.eq user_id + .eq status), при удалении скриншоты вычищаются из Storage (путь извлекается из публичного URL).
4. **Массовые действия в админке** (`/admin/feedback`): чекбоксы в таблице и мобильных карточках, «выбрать все» по отфильтрованному списку, панель «Выбрано: N → В работе / Решено / Отклонено / Снять», один запрос .in('id', [...]). Выделение сбрасывается при смене фильтра/поиска.
5. **Выгрузка по фильтру**: «Выгрузить JSON (по фильтру)» и CSV экспортируют отфильтрованный набор (фильтр «Новое» → только новые). Кнопка показывает «(по фильтру)», когда фильтр/поиск активны.

### Рабочий цикл обращений (схема)

Отправил → видит в «Моих обращениях» → правит/удаляет, пока «Новое» → админ выгружает JSON по фильтру «Новое» → `scrin_bag/` → агент качает скрины, отрабатывает → админ массово: «В работе» → после разбора «Решено»/«Отклонено».
