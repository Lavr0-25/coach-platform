# Спека: уроки и их контент (`lessons` + `lesson_content`)

> Статус: `stable` · обновлено 2026-09-03 · ответственный: Анатолий + Claude Code

## Модель данных

- `lessons` — урок: title, description, price, is_free_preview, cover_image,
  is_published (черновик/опубликован), coach_id, course_id.
- `lesson_content` — контент урока (1 запись на урок, order_index):
  - `content_type` — **CHECK-ограничение**, допустимые значения:
    `video | text | pdf | image | storage | other`.
    ⚠️ При добавлении нового типа править не только код, но и CHECK-ограничение
    в БД (2026-09-02: 'text' добавили в код, сохранение падало — проверка БД).
  - `content_url` (NOT NULL) — ссылка/путь контента; для `text` — пустая строка.
  - `content_html` — HTML текстового урока (только для `text`).
  - `title` — подпись контента; для `text` не используется.
- Миграции: `docs/migrations/` (content_html + CHECK c 'text' — 2026-09-02).

## Типы контента

| Тип | Что хранится | Кто задаёт |
|---|---|---|
| video | Ссылка (YouTube/VK/RuTube/Дзен/файл) — embed определяется по URL | наставник |
| text | `content_html` — статья в WYSIWYG | наставник |
| pdf / image | Файл в Storage (`lesson_files`) или ссылка | наставник |
| storage / other | Внешняя ссылка (Я.Диск, Drive и т.п.) | наставник |

## Текстовый урок (WYSIWYG, Tiptap 3)

### Редактор (наставник)

- `components/editor/RichTextEditor.tsx`, расширения — **один источник**:
  `lib/editor/lessonExtensions.ts` (StarterKit, Image, Youtube, TextAlign, VkVideo).
  Этот же набор используют очистка и вывод — расхождение невозможно.
- Блоки: H1–H3, Ж/К/Ч, маркерованный/нумерованный список, цитата, разделитель,
  выравнивание (лево/центр/право — для абзацев и заголовков), картинки
  (Storage `lesson_files`, ≤10 МБ, всегда по центру), YouTube, VK.
- VK — своё расширение `VkVideo` (готового нет): `vk.com|vkvideo.ru/video-oid_id`
  → embed `video_ext.php?oid=...&id=...`.
- Панель закреплена под шапкой (sticky top-16). Контейнер редактора — БЕЗ
  `overflow-hidden` (он превращает sticky в «липание внутри контейнера»).
- Создание урока (`/new`): тип `text` → урок создаётся без контента, наставник
  ведётся сразу в редактор `/[id]/edit`; строка `lesson_content` появляется
  при первом сохранении.

### Очистка HTML (безопасность, главная часть фичи)

- `lib/editor/sanitizeLessonHtml.ts` — только для сервера (`@tiptap/html/server`,
  требует happy-dom). Идея: сам Tiptap — санитайзер. `generateJSON` парсит HTML
  через схему — всё вне схемы отбрасывается; `generateHTML` собирает чистый HTML.
- Применяется **дважды**: при сохранении (server action `updateLesson`) и при
  выводе (`app/lesson/[id]`, server component) — двойной замок.
- Проверено тестом (2026-09-02): `<script>`, `onclick`/`onerror`, `href="javascript:"`,
  чужие `<iframe>` — удаляются; h1/strong/img — сохраняются.
- `content_url` для `text` всегда `''`; пустой текст (`<p></p>`) → ошибка
  «Текст урока пуст», не сохраняется.

### Просмотр (ученик)

- `app/lesson/[id]` → `content_type='text'` → `<article class="lesson-prose">`
  с очищенным HTML (`dangerouslySetInnerHTML` — безопасно, т.к. выше два слоя очистки).
- Стили `.lesson-prose` / `.lesson-prose-editor` в `globals.css` — только на
  токенах темы (`--t-ink-*`, `--brand`): перекрашиваются в тёмной теме и палитрах.
  Мобильная типографика — media 640px.

## Приёмочные критерии (фича WYSIWYG, 2026-09-02)

1. Наставник создаёт урок типа «Текст», пишет с форматированием, вставляет
   картинку и YouTube-ссылку → сохраняется. ✅ (проверено Анатолием, после фикса CHECK)
2. Ученик видит отформатированный текст, в т.ч. на мобильном и в тёмной теме.
3. В сохранённом HTML нет скриптов/обработчиков — ✅ (тест очистки выше).
4. Бесплатное превью/цена работают как для остальных типов.
5. `tsc` — 0 ошибок; спека обновлена в наборе правок.

## Границы / открытые вопросы

- Ошибки сохранения: плашка вверху формы + авто-прокрутка наверх (добавлено,
  т.к. на длинной странице ошибку не было видно).
- Консольные ошибки со страницы урока с VK-вставкой (CORS apptracer.ru, 403/406
  stats.vk-portal.net) — шум самого VK-плеера внутри его iframe, к платформе
  не относятся, не чиним.
- Зависимости: @tiptap/react, starter-kit, extension-image, extension-youtube,
  extension-text-align, @tiptap/html + happy-dom (сервер). Редактор ~150 КБ JS
  только на странице редактирования.

## Публикация без контента запрещена (2026-09-03)

Урок нельзя опубликовать без сохранённого контента (раньше студент видел
заглушку «Контент урока недоступен» — из docs/backlog.md, закрыто):

- **Сервер** (`setLessonPublished` в app/actions/updateLesson.ts): при
  `published=true` проверяется `lesson_content` — для `content_type='text'`
  нужен непустой текст вне HTML-тегов, для остальных типов — непустая
  `content_url`. Пусто/нет записи → ошибка «Сначала заполните и сохраните
  контент урока…». Проверка на сервере — главная (UI не доверенный).
- **UI** (страница редактирования урока): у черновика без сохранённого
  контента кнопка «Опубликовать урок» неактивна (`disabled`), в статусе
  черновика видна подсказка «…сначала заполните и сохраните контент».
  Флаг `hasSavedContent` ставится при загрузке урока (по тем же правилам
  непустоты) и после успешного «Сохранить изменения».
- Снятие с публикации не ограничивается — «Вернуть в черновик» работает всегда.

## Публикация по расписанию (2026-09-03)

Автор задаёт уроку момент публикации (`lessons.publish_at`, timestamptz); открыть
урок в срок может и без участия автора:

- **Планировщик в БД** — pg_cron, job `publish-scheduled-lessons` каждую минуту:
  `update lessons set is_published = true where publish_at is not null and is_published = false and publish_at <= now()` +
  проверка непустого контента через `lesson_content` (то же правило непустоты, что
  у ручной публикации). Job работает от postgres, RLS не применяет — меняет только
  `is_published`/`updated_at` по служебному условию. Миграция:
  `docs/migrations/2026-09-03-scheduled-publish.sql`.
- **UI (страница редактирования):** у черновика с сохранённым контентом рядом с
  «Опубликовать сейчас» есть «🗓 По расписанию» — панель с `datetime-local`.
  Запланированное состояние: заголовок статуса «Публикация запланирована: …» +
  кнопка «Отменить расписание». Ручная публикация перекрывает расписание
  (`publish_at = null` при `setLessonPublished(published=true)`).
- **UI (список «Мои уроки»):** у черновика с расписанием — бейдж
  «🗓 дата-время» + двухшаговая отмена («Точно отменить?») прямо в карточке.
- **Сервер** (`setLessonPublishAt` в app/actions/updateLesson.ts): только свой
  черновик, время в будущем, контент непустой (правило «публикация без контента
  запрещена» выше); `null` отменяет расписание.
- Урок с расписанием до наступления срока ведёт себя как черновик: 404 для всех,
  кроме автора; в каталоге и sitemap отсутствует. Точность публикации — до минуты.

## Удаление урока наставником (2026-09-03)

Наставник может удалить свой урок двумя путями:
- кнопка «Удалить урок» внизу страницы редактирования (красная, справа от
  «Отмена»), подтверждение через confirm с предупреждением, если урок
  опубликован; после успеха — редирект в «Мои уроки»;
- корзина в правом верхнем углу карточки в списке «Мои уроки»
  (`/dashboard/mentor/lessons`, 2026-09-03) — двухшаговое подтверждение
  («Точно удалить?»), тост об успехе, карточка уходит из списка без перезагрузки.

- **Сервер** (`deleteLesson` в app/actions/deleteLesson.ts): удаляет строку
  `lessons` только при совпадении `coach_id` (проверка владельца + RLS
  `lessons_owner_delete`). Связанные записи чистит база: все 13 дочерних
  таблиц (lesson_content, lesson_progress, comments, likes, favorites,
  purchases, course_lessons, tests и др.) висят на `ON DELETE CASCADE`,
  каскады выполняются от владельца таблицы и RLS дочерних таблиц не
  применяются.
- **Урок с покупками автор удалить НЕ может** (решение Анатолия, 2026-09-03):
  `deleteLesson` проверяет `purchases` по `lesson_id` — если есть покупки,
  возвращает ошибку «Урок уже купили — … удаление купленных уроков делает
  только администрация». Причина: каскад стёр бы записи о деньгах.
- **Купленный урок удаляет только админ** — `deleteLesson` в
  `app/admin/actions.ts` не имеет проверки покупок: удаляет `lesson_content`,
  затем `lessons`; покупки уходят каскадом (история оплат по уроку
  не сохраняется — осознанный компромисс до появления архивации покупок).
- **Файлы Storage не удаляются** (обложка, PDF/картинки контента) — остаются
  осиротевшие объекты бакетов; чистка отдельной задачей (бэклог при росте
  объёма).
