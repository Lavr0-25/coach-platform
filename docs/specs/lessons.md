# Спека: уроки и их контент (`lessons` + `lesson_content`)

> Статус: `stable` · обновлено 2026-09-04 · ответственный: Анатолий + Claude Code

## Модель данных

- `lessons` — урок: title, description, price, is_free_preview, cover_image,
  is_published (черновик/опубликован), coach_id, is_hidden + link_access
  (см. «Скрытые уроки» ниже), publish_at (расписание публикации),
  published_at (фактический момент публикации — ставит ручная публикация
  и планировщик, null после снятия с публикации).
  Колонки `course_id` больше нет — связь урок↔курс через `course_lessons`.
- `lesson_content` — контент урока (1 запись на урок, order_index):
  - `content_type` — **CHECK-ограничение** в БД сохранено
    (`video | text | pdf | image | storage | other`), но платформа пишет
    только `text` (см. «Только текстовые уроки» ниже). CHECK не расширяли и
    не сужали: он страхует от мусора при прямых записях в БД.
  - `content_url` (NOT NULL) — для `text` — пустая строка.
  - `content_html` — HTML текстового урока.
  - `title` — подпись контента; для `text` не используется.
- Миграции: `docs/migrations/` (content_html + CHECK c 'text' — 2026-09-02).

## Только текстовые уроки (2026-09-04)

Решение: на платформе один тип контента — текстовая статья в WYSIWYG.
Выбор типа из форм создания/редактирования убран:

- **UI (`/dashboard/mentor/lessons/new`)** — селектора «Тип контента» нет;
  карточка «Контент урока» — пояснение, что текст пишется в редакторе.
  Урок создаётся без строки `lesson_content`, автор ведётся сразу в
  `/[id]/edit` (как раньше для `text`).
- **UI (`/dashboard/mentor/lessons/[id]/edit`)** — в карточке «Контент урока»
  сразу WYSIWYG-редактор, без выбора типа, поля ссылки и загрузчика файла.
  «Сохранить изменения» шлёт `content_type='text'`, `content_url=''`.
- **БД** — все уроки конвертированы в `text` (2026-09-03, SQL-конверсия,
  10/10); не-текстовых строк нет. Логика чтения старых типов в коде
  (embed и т.п.) не поддерживается формами и не актуализируется.

## Текстовый урок (WYSIWYG, Tiptap 3)

### Редактор (наставник)

- `components/editor/RichTextEditor.tsx`, расширения — **один источник**:
  `lib/editor/lessonExtensions.ts` (StarterKit, Image, Youtube, TextAlign, VkVideo).
  Этот же набор используют очистка и вывод — расхождение невозможно.
- Блоки: H1–H3, Ж/К/Ч, маркерованный/нумерованный список, цитата, разделитель,
  выравнивание (лево/центр/право — для абзацев и заголовков), картинки
  (Storage `lesson_files`, ≤10 МБ, всегда по центру), YouTube, VK.
- VK — своё расширение `VkVideo` (готового нет): `vk.com|vkvideo.ru/video-oid_id`
  → embed `video_ext.php?oid=...&id=...`.
- Панель закреплена под шапкой (sticky top-16). Контейнер редактора — БЕЗ
  `overflow-hidden` (он превращает sticky в «липание внутри контейнера»).
- Создание урока (`/new`): урок создаётся без контента, наставник
  ведётся сразу в редактор `/[id]/edit`; строка `lesson_content` появляется
  при первом сохранении.

### Очистка HTML (безопасность, главная часть фичи)

- `lib/editor/sanitizeLessonHtml.ts` — только для сервера (`@tiptap/html/server`,
  требует happy-dom). Идея: сам Tiptap — санитайзер. `generateJSON` парсит HTML
  через схему — всё вне схемы отбрасывается; `generateHTML` собирает чистый HTML.
- Применяется **дважды**: при сохранении (server action `updateLesson`) и при
  выводе (`app/lesson/[id]`, server component) — двойной замок.
- Проверено тестом (2026-09-02): `<script>`, `onclick`/`onerror`, `href="javascript:"`,
  чужие `<iframe>` — удаляются; h1/strong/img — сохраняются.
- `content_url` для `text` всегда `''`; пустой текст (`<p></p>`) → ошибка
  «Текст урока пуст», не сохраняется.

### Просмотр (ученик)

- `app/lesson/[id]` → `content_type='text'` → `<article class="lesson-prose">`
  с очищенным HTML (`dangerouslySetInnerHTML` — безопасно, т.к. выше два слоя очистки).
- Стили `.lesson-prose` / `.lesson-prose-editor` в `globals.css` — только на
  токенах темы (`--t-ink-*`, `--brand`): перекрашиваются в тёмной теме и палитрах.
  Мобильная типографика — media 640px.

## Приёмочные критерии (фича WYSIWYG, 2026-09-02)

1. Наставник создаёт урок типа «Текст», пишет с форматированием, вставляет
   картинку и YouTube-ссылку → сохраняется. ✅ (проверено Анатолием, после фикса CHECK)
2. Ученик видит отформатированный текст, в т.ч. на мобильном и в тёмной теме.
3. В сохранённом HTML нет скриптов/обработчиков — ✅ (тест очистки выше).
4. Бесплатное превью/цена работают как для остальных типов.
5. `tsc` — 0 ошибок; спека обновлена в наборе правок.

## Границы / открытые вопросы

- Ошибки сохранения: плашка вверху формы + авто-прокрутка наверх (добавлено,
  т.к. на длинной странице ошибку не было видно).
- Консольные ошибки со страницы урока с VK-вставкой (CORS apptracer.ru, 403/406
  stats.vk-portal.net) — шум самого VK-плеера внутри его iframe, к платформе
  не относятся, не чиним.
- Зависимости: @tiptap/react, starter-kit, extension-image, extension-youtube,
  extension-text-align, @tiptap/html + happy-dom (сервер). Редактор ~150 КБ JS
  только на странице редактирования.

## Публикация без контента запрещена (2026-09-03)

Урок нельзя опубликовать без сохранённого контента (раньше студент видел
заглушку «Контент урока недоступен» — из docs/backlog.md, закрыто):

- **Сервер** (`setLessonPublished` в app/actions/updateLesson.ts): при
  `published=true` проверяется `lesson_content` — для `content_type='text'`
  нужен непустой текст вне HTML-тегов, для остальных типов — непустая
  `content_url`. Пусто/нет записи → ошибка «Сначала заполните и сохраните
  контент урока…». Проверка на сервере — главная (UI не доверенный).
- **UI** (страница редактирования урока): у черновика без сохранённого
  контента кнопка «Опубликовать урок» неактивна (`disabled`), в статусе
  черновика видна подсказка «…сначала заполните и сохраните контент».
  Флаг `hasSavedContent` ставится при загрузке урока (по тем же правилам
  непустоты) и после успешного «Сохранить изменения».
- Снятие с публикации не ограничивается — «Вернуть в черновик» работает всегда.

## Публикация по расписанию (2026-09-03)

Автор задаёт уроку момент публикации (`lessons.publish_at`, timestamptz); открыть
урок в срок может и без участия автора:

- **Планировщик в БД** — pg_cron, job `publish-scheduled-lessons` каждую минуту:
  `update lessons set is_published = true, published_at = now() where publish_at is not null and is_published = false and publish_at <= now()` +
  проверка непустого контента через `lesson_content` (то же правило непустоты, что
  у ручной публикации). Job работает от postgres, RLS не применяет — меняет только
  `is_published`/`published_at`/`updated_at` по служебному условию. Миграции:
  `docs/migrations/2026-09-03-scheduled-publish.sql`,
  `docs/migrations/2026-09-05-lessons-published-at.sql`.
- **UI (страница редактирования):** рядом с публикацией есть «🗓 По расписанию» —
  панель с `datetime-local`. Доступна и черновику (с сохранённым контентом), и
  опубликованному уроку: у опубликованного установка расписания **сразу снимает
  его с публикации** (вариант А), планировщик откроет урок в назначенное время.
  Запланированное состояние: заголовок статуса «Публикация запланирована: …» +
  кнопка «Отменить расписание». Ручная публикация перекрывает расписание
  (`publish_at = null` при `setLessonPublished(published=true)`). Снятие с
  публикации тоже чистит `publish_at` — иначе старое расписание в прошлом снова
  опубликует урок планировщиком сразу после «Вернуть в черновик».
- **UI (список «Мои уроки»):** у черновика с расписанием — бейдж
  «🗓 дата-время» + двухшаговая отмена («Точно отменить?») прямо в карточке;
  у опубликованного — бейдж «📅 дата публикации» (колонка `published_at`).
- **Сервер** (`setLessonPublishAt` в app/actions/updateLesson.ts): свой урок,
  время в будущем, контент непустой (правило «публикация без контента
  запрещена» выше); `null` отменяет расписание. Установка на опубликованном
  уроке: `is_published = false, published_at = null` в том же update.
- Урок с расписанием до наступления срока ведёт себя как черновик: 404 для всех,
  кроме автора; в каталоге и sitemap отсутствует. Точность публикации — до минуты.

## Удаление урока наставником (2026-09-03)

Наставник может удалить свой урок двумя путями:
- кнопка «Удалить урок» внизу страницы редактирования (красная, справа от
  «Отмена»), подтверждение через confirm с предупреждением, если урок
  опубликован; после успеха — редирект в «Мои уроки»;
- корзина в правом верхнем углу карточки в списке «Мои уроки»
  (`/dashboard/mentor/lessons`, 2026-09-03) — двухшаговое подтверждение
  («Точно удалить?»), тост об успехе, карточка уходит из списка без перезагрузки.

- **Сервер** (`deleteLesson` в app/actions/deleteLesson.ts): удаляет строку
  `lessons` только при совпадении `coach_id` (проверка владельца + RLS
  `lessons_owner_delete`). Связанные записи чистит база: все 13 дочерних
  таблиц (lesson_content, lesson_progress, comments, likes, favorites,
  purchases, course_lessons, tests и др.) висят на `ON DELETE CASCADE`,
  каскады выполняются от владельца таблицы и RLS дочерних таблиц не
  применяются.
- **Урок с покупками автор удалить НЕ может** (решение Анатолия, 2026-09-03):
  `deleteLesson` проверяет `purchases` по `lesson_id` — если есть покупки,
  возвращает ошибку «Урок уже купили — … удаление купленных уроков делает
  только администрация». Причина: каскад стёр бы записи о деньгах.
- **Купленный урок удаляет только админ** — `deleteLesson` в
  `app/admin/actions.ts` не имеет проверки покупок: удаляет `lesson_content`,
  затем `lessons`; покупки уходят каскадом (история оплат по уроку
  не сохраняется — осознанный компромисс до появления архивации покупок).
- **Файлы Storage не удаляются** (обложка, PDF/картинки контента) — остаются
  осиротевшие объекты бакетов; чистка отдельной задачей (бэклог при росте
  объёма).

## Скрытые уроки (2026-09-04)

Режим урока «вне каталога»: не виден в каталоге, поиске, sitemap и профиле автора;
открывается только тем, кого автор допустил. Приватный канал распространения
(ссылка в мессенджер, закрытая группа учеников и т.п.). Миграции:
`docs/migrations/2026-09-04-hidden-lessons.sql` (включая фикс рекурсии RLS — раздел 5).

### Режимы и данные

- `lessons.is_hidden` (default false) — скрытый режим; `lessons.link_access`
  (default true) — приём по ссылке.
- `lesson_access` — допуски: unique(lesson_id, user_id), `source` = manual/link,
  `revoked` (отзыв, строка не удаляется — иначе ссылка вернула бы доступ),
  `added_by`. RLS включён.
- Скрытый урок всегда самостоятельный: при включении режима серверный экшен
  отвязывает урок от всех курсов (`course_lessons`); автор может отвязать от
  чужого курса (RLS-политика `course_lessons_lesson_coach_delete`).
- Скрытый урок публикуется (`is_published=true`) при включении режима.

### Кто видит скрытый урок (RLS)

- Автор (coaches.user_id) — всегда; допущенные (`lesson_access`, revoked=false).
- Политики проверки вынесены в SECURITY DEFINER-функции
  `is_coach_of_lesson()` / `lesson_accepts_link()` — прямые подзапросы к lessons
  из политик lesson_access давали «infinite recursion» и 500 на всех уроках.
- Все прочие (включая анонима) — RLS не отдаёт урок → 404.

### Доступ (страница урока `app/lesson/[id]`)

- **По ссылке** (`link_access=true`): залогиненный, ещё не допущенный,
  автоматически добавляется (`ensureLinkAccess` — до чтения урока; upsert
  `source='link'` с `ignoreDuplicates`). Отозванный снова не попадает:
  строка с revoked=true блокирует и чтение, и повторный самозахват (unique).
- **Только приглашения** (`link_access=false`): ссылка не открывает — не
  допущенный получает 404; допущенные видят как обычно.
- **Аноним**: если урок существует → редирект на `/login?next=/lesson/<id>`
  (после входа — возврат на урок; `?next=` принимает только внутренние пути).
  Несуществующий id — обычная 404.
- **Оплата обязательна** (решение Анатолия): допуск даёт право видеть страницу
  урока (шапка, описание, комментарии); контент — по общим правилам (цена/
  покупка/бесплатное превью). Скрытие не отменяет цену.
- Концепты, объясняющие код: `ensureLinkAccess` вызывается и в `generateMetadata`
  (метаданные и страница рендерятся параллельно, у каждого свой запрос урока);
  перечитывание после первого запроса не работает — Next.js мемоизирует fetch
  внутри рендера, поэтому вставка делается ДО чтения, а в метаданных перечитывание
  меняет URL (`.limit(1)`).

### Исключение из публичных списков (фильтр `is_hidden` в коде)

- Главная (catalog ленты, `app/page.tsx`), sitemap (`app/sitemap.ts`),
  публичный профиль автора (`components/MentorProfile.tsx` — список и счётчик
  «N уроков»), каталог авторов `/mentors` (счётчики уроков).
- Кабинет автора, админка, избранное/уведомления — скрытые уроки видны
  (это приватные зоны; у автора панель управления, у админа — обзор).

### UI кабинета (`components/HiddenLessonPanel.tsx`)

- Панель внизу страницы редактирования (после «Цена и доступ»); в скрытом
  режиме наверху компактный статус «🔒 Урок скрыт». Тумблеры (role="switch"):
  «Скрытый режим» и «Приём по ссылке» + кнопка «Скопировать ссылку».
- Поиск людей для приглашения: профили (имя+email) и публичное имя автора
  (coaches.display_name), слияние без дублей; публичное имя показывается первым.
- Список допущенных: аватар, имя, email, пометка «по ссылке»/«вручную»,
  «Отозвать»; свёрнутый блок «Отозванные: N».
- Серверные экшены `app/actions/hiddenLesson.ts`: setLessonHidden (проверка
  контента, отвязка от курсов, is_published=true), setLessonLinkAccess,
  addLessonAccess (восстанавливает отозванную строку — это ручное приглашение),
  revokeLessonAccess (revoked=true).

### Приёмочные критерии

1. Аноним по ссылке → `/login?next=…`; после входа урок открывается. ✅ (ui-test 2026-09-04, 9/9)
2. Не допущенный залогиненный — 404; допущенный по ссылке — видит, пометка
   «по ссылке» в панели автора. ✅
3. Отозванный — 404, повторный заход по ссылке доступ не возвращает. ✅
4. Режим «только приглашения» (link_access=false): ссылка не открывает (404),
   допущенные видят. ✅
5. Скрытого урока нет на главной, в sitemap, в профиле автора и в счётчиках /mentors.
6. Мобильный вид — без горизонтального скролла. ✅

### Границы / известные особенности

- ~~Комментарии скрытого урока читались без проверки видимости урока~~ —
  **закрыто 2026-09-04**: политики SELECT/INSERT таблицы `comments` проверяют
  `lesson_visible_to()` (виден ли урок: не-скрытый — да, скрытый — автору или
  допущенному). Миграция: `docs/migrations/2026-09-04-comments-hidden-lesson.sql`.
  Проверено: анонимный REST-запрос к комментариям скрытого урока — 0 строк,
  обычные уроки не задеты. UPDATE/DELETE комментариев остались «только свой»
  (утечки контента через них нет). Комментарии черновиков (не-скрытых,
  неопубликованных) по-прежнему читаются знающим id — узкий случай, граница
  не двигалась.
- Мета-теги скрытого урока не отдаются поисковикам (для них урок — 404).
- Скрытый урок не может жить в курсе (отвязка при включении режима).
