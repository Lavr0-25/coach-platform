## Goal

Платёжная система RightWay на Robokassa:

1. **Разовые покупки** — студент покупает урок или курс навсегда.
2. **Подписки на автора** — ежемесячные рекурренты, открывают материалы
   автора, помеченные флагом «в подписке».
3. **Выплаты менторам** — роялти по лицензионной модели, учёт и отчёты.
4. **Управление комиссией** — глобальная ставка + промо + ручные ставки.
5. **Журнал действий** — для споров и аналитики «живой vs бот».
6. **Чистка неактивных** — Telegram-модель, 12 месяцев.

## Ограничения (Constraints)

### Схема расчётов

- **Целевая схема: ООО, УСН 15%.** ООО продаёт доступ, доля ментора —
  роялти по лицензионному договору = подтверждённый расход (чеки НПД).
  Расчёт на урок 1000 ₽ при комиссии 30%: Robokassa −34 ₽ → ООО 966 →
  роялти 700 → УСН 15% с базы 266 = 39,90 ₽; ментору на руки 672 ₽.
  ⚠️ **Открытый вопрос (Анатолий, 2026-09-10): ООО может не
  состояться** — возможен возврат к самозанятости или ИП; решение
  не принято. На код и схему БД не влияет, понадобится только в Ф6
  (оферты) и при регистрации магазина Robokassa.
- **Старт допустим на самозанятости** (схема «агент», НПД): все платежи
  через один магазин, менторам ручные выплаты, налог каждый со своей
  части. Переключение магазина Robokassa на ООО не меняет код.
- **Robokassa:** комиссия 3,4% карты / 3,0% СБП, без НДС сверху,
  рекурренты, авто-чеки («Робочеки СМЗ» — на этапе самозанятости,
  кассовые чеки 54-ФЗ — на этапе ООО). Возвраты через API, комиссия
  не возвращается. Аккаунт не зарегистрирован — регистрация после
  утверждения модели.
- **Секреты** (shop id, пароль #1/#2) — только в Vercel env, не в репо.
  Webhook Robokassa (ResultURL) проверяет подпись (MD5 по канону) и
  сумму; идемпотентность по `InvId`.

### Комиссия платформы

- Глобальная ставка в админке, по умолчанию **30%** (ментору 70%).
  Единая для разовых покупок и подписок. Параметр в БД, не в коде.
- **Ручная ставка админа** (высший приоритет): % + комментарий
  (Ambassador, топовый автор и т.п.), действует до снятия.
- **Реферальные бенефиты:** ментор приводит друга (любой новый
  пользователь с подтверждённым email) → **−10 п.п. на 3 месяца**,
  стакается, но не ниже минимального порога **10%**. Все цифры —
  настройки в админке.
- **Клосбэк:** удаление фейкового аккаунта снимает бенефиты,
  заработанные на нём; пересчёт со следующего периода, уже
  выплаченное не отбирается.
- Порядок расчёта: ручная ставка → иначе глобальная − активные
  бенефиты → floor (мин. порог).

### Договоры и выплаты

- **Лицензионный договор** с ментором (оферта-акцепт в кабинете):
  право продавать его контент, роялти, порядок выплат, обязанность
  чека НПД, обязанность сообщать о потере статуса, гарантии прав
  на контент.
- Самозанятый → чек НПД **6%** (доход от юрлица) на каждую выплату;
  ИП → свои документы; **физлицо без статуса → выплаты не включаются**
  (иначе НДФЛ 13% + взносы ~30% у платформы).
- Проверка статуса по ИНН (реестр ФНС) на онбординге ментора.
- Ежемесячный отчёт ментору (продажи, сумма, комиссия) + удержание
  выплаты до предоставления чека.

### Блокировки (рубильники админа)

- **Дефолт — закрыто (решение Анатолия, 2026-09-09):** новый ментор
  **не может** публиковать платный контент и подключать подписку,
  пока админ не разрешит (`paid_publishing_allowed`, по умолчанию
  false). Разрешение/блокировка — только админ, с обязательным
  комментарием-причиной в `audit_log`. Ментор сам свой статус
  не меняет.
- Иностранцы (не РФ/ЕАЭС — НПД недоступен) остаются закрытыми до
  проверки налогового статуса; non grata — закрыты бессрочно.
- `paid_publishing_blocked` (для ранее разрешённых) — ментор
  публикует только бесплатный контент; существующий платный скрыт
  из продажи, купленное сохраняется.
- Блокировка подписки отдельно: продажи уроков возможны, активные
  подписчики доигрывают период, новые не подключаются.

### Модель доступа (гибрид «подписка на автора» + «выбор автора»)

- У ментора — цена подписки (задаёт сам, вилка **99–9 990 ₽/мес**,
  редактируема в админке). Цена не задана → кнопка подписки не показывается.
- На платном уроке/курсе — флаг `in_subscription` (по умолчанию **выключен**):
  включён → подписчикам открывается; выключен → только разовая покупка.
- Курс с флагом открывает подписчику весь курс целиком.
- Доступ: превью — всем; разовая покупка — навсегда; подписка —
  пока активна; отмена — доступ до конца оплаченного периода.
- Двойной доступ (купил + подписка) — не мешает.

### Журнал действий и аналитика

- **`audit_log`** (изменения): user_id, логин, роль, действие
  (форма/endpoint), тип и id объекта, **before/after (JSON)**, IP,
  user agent, время. Обёртка для server actions — логирование
  автоматическое. Читает только админ.
- **`activity_events`** (активность): вход, просмотр, комментарий —
  без before/after. Метрики «живой vs бот»: последний вход, события
  за 30 дней, **совпадение IP у рефералов**, темп регистраций друзей.
- Хранение: логи активности — 1 год; финансовые записи — 5 лет
  (налоги), обезличенно после удаления аккаунта.
- IP — персональные данные: абзац в `/privacy`.

### Чистка неактивных (Telegram-модель, 12 мес)

- Неактивность 12 мес (вход/покупка/просмотр/комментарий) → удаление
  аккаунта **без контента и продаж**: сначала email за 30 и за 7 дней,
  затем обезличивание (суммы покупок остаются для налогов).
- **Менторы с контентом и продажами не удаляются автоматически**
  (договор, роялти, налоги).
- «Купил — навсегда» в оферте уточняется: «доступ сохраняется, пока
  существует аккаунт; неактивный >12 мес удаляется по политике
  (2 предупреждения)».
- Кандидаты на удаление — списком в админке, можно отложить.
- Ежемесячная задача pg_cron (к ночному агенту 03:17).

- **Ф2. Разовые покупки.** e2e: «Купить урок за N ₽» → Robokassa

  формуле) → доступ открыт; чек покупателю; повторный webhook
  не дублирует запись; кнопка «Купить курс» — то же для курса;
  бесплатные превью работают как раньше; отмена оплаты ничего
  не записывает.
- **Ф3. Подписки.** e2e: «Подписка на автора за M ₽/мес» → оплата →
  доступ ко всем материалам с флагом → токен рекурренты сохранён →
  отмена в кабинете → доступ до конца периода, далее закрыт; чек на
  каждое списание; материалы без флага не открываются подпиской.
- **Ф4. Комиссии и промо.** Админ меняет глобальную ставку — новые
  продажи считаются по ней; ручная ставка перекрывает всё;
  бенефит стакается и не ниже порога; удаление фейка снимает его
  бенефиты; в кабинете ментора видна текущая ставка и срок промо.
- **Ф5. Логи и чистка.** Действие (правка урока/цены, блокировка,
  бан) создаёт запись `audit_log` с before/after и IP; в админке
  фильтр по пользователю и типу; кандидат на удаление получает 2
  письма и через 12 мес неактивности удаляется с обезличиванием
  финансовых записей; бенефиты сняты, купленное студентами живо.
- **Ф6. Боевой запуск.** Аккаунт Robokassa зарегистрирован, магазин
  переключён с test на боевой; оферты и `/privacy` обновлены
  (IP-логирование, политика неактивности); регресс не сломан.
  Отдельно: **платный тариф GigaChat API** или иное документированное
  право коммерческого использования (бесплатный ключ — только
  некоммерческое использование, п. 3.1 соглашения GigaChat от
  22.06.2026); маркировка ИИ-контента в продуктах сверена.
