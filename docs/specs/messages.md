# Спека: Личные сообщения (`/messages`)

> Статус: `stable` · обновлено 2026-09-05 · ответственный: Анатолий + Claude Code

## Задача

Переписка между студентами и наставниками внутри кабинета. Интерфейс ощущается как
привычный мессенджер (переработка по итогам UX-ревизии №18, вариант B «как в
мессенджерах», согласован с Анатолием 2026-09-05).

## Экраны

**Список диалогов** (`/messages`):
- Слева (десктоп) или весь экран (мобильный) — список диалогов с последним сообщением,
  временем и счётчиком непрочитанных; сортировка: непрочитанные сверху, затем по времени.
- Крестик «Скрыть диалог» убирает диалог из списка (хранится в `localStorage`,
  ключ `hidden-conversations`); «Показать все» возвращает.
- Поиск в шапке фильтрует диалоги по имени и ищет наставников по специализации.

**Переписка** (`/messages/[userId]`):
- Мобильный — полноэкранный отдельный экран; шапка одна: кнопка «‹» (44px),
  фото собеседника, имя, меню «⋯».
- Меню «⋯»: «Профиль собеседника» (ссылка на публичную страницу), «Заблокировать» /
  «Разблокировать» (с confirm).
- Иконка поиска открывает инпут с автофокусом; найденный текст подсвечивается,
  поиск по кнопке Enter.
- Сообщения одного автора подряд сгруппированы в «пузырь»: время и галочки
  (✓ отправлено / ✓✓ прочитано) только у последнего в группе.
- Между прочитанными и новыми — разделитель «НЕПРОЧИТАННЫЕ» (как в Telegram).
- Если диалог заблокирован (кто-либо из сторон) — сообщения скрыты.

**Ввод:**
- textarea с авто-ростом до ~5 строк (лимит 132px), прокрутка дальше.
- Enter — отправить, Shift+Enter — новая строка.

## Поведение и данные

- Таблица `messages` (`sender_id`, `receiver_id`, `content`, `is_read`, `created_at`).
  RLS: участники видят только свои сообщения.
- Загрузка чата: непрочитанные сообщения собеседника помечаются `is_read: true`,
  одновременно помечаются прочитанными уведомления этого диалога в колокольчике
  (`type='new_message'`, `link='/messages/<отправитель>'`); рассылается событие
  `messages-read` (обновляет бейджи Navbar и сайдбара).
- **Уведомления о новых ЛС** — триггер `on_message_notify` (миграция
  `docs/migrations/2026-09-05-messages-notifications.sql`): AFTER INSERT ON messages
  создаёт запись в `notifications` получателю (`type='new_message'`, заголовок
  «Новое личное сообщение», превью текста 80 символов, ссылка на чат с отправителем).
  Если получатель заблокировал отправителя (таблица `blocked_users`) — уведомление
  не создаётся. Функция `notify_new_message()` — SECURITY DEFINER, потому что
  у `notifications` нет INSERT-политики (клиент записи не создаёт).
  Проверять «находится ли получатель сейчас в этом чате» со стороны SQL нельзя —
  уведомление создаётся всегда, а при открытии чата гасится (см. выше).
- Realtime: канал `chat-<userId>` ловит INSERT новых сообщений собеседника; в сайдбаре
  канал `messages-sidebar` обновляет список.
- **Удаление своего сообщения** — без confirm: сообщение скрывается, показывается
  тост «Сообщение удалено» с кнопкой «Вернуть» (5 секунд). Возврат вставляет
  сообщение заново с тем же текстом (created_at — момент возврата: компромисс,
  потому что после удаления строку в БД уже не вернуть).

## Ограничения (известные компромиссы)

- Undo-возврат создаёт сообщение с новым `created_at` — оно уезжает в конец диалога.
- Редактирование отправленного сообщения не реализовано (отдельная задача в бэклоге).
- На мобильном эмодзи-пикер скрыт — нативная клавиатура имеет свои эмодзи.
- Navbar на /messages может показать «Войти» при живой сессии (косметика, в бэклоге).
