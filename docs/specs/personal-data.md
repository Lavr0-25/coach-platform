## Зачем

152-ФЗ, ст. 18 ч. 5: при сборе персональных данных (в т.ч. через интернет)
оператор обязан обеспечивать запись, хранение и уточнение ПДн граждан РФ
**на территории РФ**. Сейчас платформа живёт в Supabase (за пределами РФ) и
на Vercel — соответствия нет на двух уровнях сразу: БД и хостинг.

## Карта ПДн (аудит 2026-09-03, все 39 таблиц + Storage)

| Жалобы и модерация | `reports`, `review_reports`, `comment_reports`, `blocked_users`, `stop_list`, `user_bans` | ~20 строк | Тексты жалоб о третьих лицах — тоже ПДн |

## Размеры (замер 2026-09-03)

- База целиком: **15 МБ** (самая большая таблица — analytics_events, 264 КБ).
- Storage: **21 МБ** (32 файла: обложки, файлы уроков, скриншоты).

### Прогноз на 10 000 активных пользователей

~0,5–2 МБ данных на пользователя в год (аналитика, прогресс, сообщения,
комментарии, уведомления):

| Горизонт | База | Storage |
|---|---|---|
| 10 000 юзеров, 1 год | 5–20 ГБ | 50–100 ГБ |
| 10 000 юзеров, 3 года | 20–60 ГБ | 100–300 ГБ |

Для Postgres это малая база. Видео хранится на YouTube/VK (embed) и в базу
не попадает; главный фактор роста — файлы Storage. Загрузка собственных
видео — отдельное решение, в план переноса не входит.

## Варианты размещения — два приоритетных (согласовано 2026-09-03)

Отклонённые альтернативы: гибрид «ПДн отдельно от контента» (две БД, развязка
auth — сложность не окупается) и управляемая БД в РФ-облаке (в 2–3 раза
дороже при наших объёмах; запасной вариант, не приоритет).

### Вариант 1: свой сервер на базе ноутбука Анатолия

- Постановка: ноутбук 24/7, Ubuntu Server + Docker (Postgres + приложение),
  автобэкап, автостарт контейнеров после ребута.
- Доступ из интернета: статический IP у провайдера или Cloudflare Tunnel
  (второй безопаснее — без открытых портов).
- ⚠️ Батарея: вечная зарядка → риск вздутия. Вынуть батарею (если съёмная)
  или лимит заряда 60–80% в фирменной утилите. Плюс сетевой фильтр.
- Цена: ~0 ₽ (+ возможно 150–300 ₽/мес за статический IP).
- Риск: отключение света/интернета = недоступность до восстановления.
  Приемлемо для учебной стадии и первых пользователей.

### Вариант 2: VPS + Docker

- Один VPS у российского провайдера (Timeweb Cloud / Selectel / reg.ru):
  2 vCPU, 4 ГБ RAM, 40–80 ГБ NVMe — 800–1500 ₽/мес.
- Тот же Docker-стек, что и в варианте 1 — конфигурации идентичны,
  перенос между вариантами = дамп базы + папка конфигов (~1 час).
- Надёжность 24/7 выше, чем у ноутбука; свет/интернет провайдера.

### Ключевое архитектурное решение (общее для обоих)

- **Docker-стек, переносимый между вариантами 1 и 2**: любой вариант
  превращается в другой за ~1 час. Можно стартовать на ноутбуке и переехать
  на VPS (или обратно) без переделки.
- **Auth**: свой (NextAuth на своей БД) вместо Supabase Auth — иначе
  `auth.users` останется за пределами РФ.
- **RLS сохраняется**: это фича Postgres, переезжает вместе с базой.
- Мой доступ: SSH-ключ (один раз, от Анатолия) → все операции с БД агент
  выполняет сам через терминал; участие Анатолия — «ОК» на критичные
  действия. Ключи/пароли — только локально, не в репозитории.

## Юридический минимум (не зависит от выбора хостинга)

- Уведомление Роскомнадзора об обработке ПДн (оператор).
- Политика конфиденциальности на сайте + фиксация согласий
  (`user_consents` — таблица уже есть).
- Минимизация: не собирать данные, не нужные продукту (например, IP —
  только для доказательства согласия и модерации).

## План переноса (когда решим стартовать)

1. RLS-аудит и исправление политик (идёт параллельно, см. docs/backlog.md).
2. Подготовка Docker-стека: Postgres + Next.js + бэкап по cron.
3. Выбор варианта (ноутбук / VPS), поднятие стенда, SSH-доступ агенту.
4. Auth: NextAuth на своей БД, перенос аккаунтов (сброс паролей
   пользователей или перенос хэшей).
5. Дамп данных из Supabase → восстановление на своём Postgres.
6. Storage: выгрузка файлов из бакетов → локальное хранилище/MinIO.
7. Переключение DNS с Vercel на свой сервер, наблюдение 1–2 недели.
8. Supabase-проект не удаляем до полной уверенности (откат = переключение DNS).
